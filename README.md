# Хроники Искателя

Личный D&D-журнал. Две основные вкладки: **Партии** и **Персонаж**. Приложение состоит из статических файлов и опубликовано в GitHub Pages.

## Возможности

- Пергаментный интерфейс с локальным EB Garamond (включая кириллицу), боковой навигацией на ПК и нижней навигацией на телефоне.
- Создание, изменение и мягкое удаление партий; собственные обложки, статус, число игроков и дата начала. Сессии и прежние заметки доступны внутри партии.
- Персонаж с портретом, шестью характеристиками и вычисляемыми модификаторами `floor((score - 10) / 2)`.
- История, события, заметки, сведения об отряде и снаряжение открываются полностью в режиме чтения. Каждый текст редактируется отдельно. Панель: жирный, буллеты, undo. Сохранить и Отмена возвращают чтение.
- Черновики пишутся в IndexedDB при каждом вводе (статус обновляется через 700 мс). При повторном открытии раздела доступно восстановление или удаление черновика. Отмена явно удаляет черновик этого раздела.
- Экспорт и объединяющий импорт JSON, включая изображения и черновики, доступны в окне облачной синхронизации.
- PWA с локальными шрифтами, иконками и офлайн-кешем. Для первого открытия требуется сеть и успешная установка service worker.

## Запуск и проверки

```sh
python -m http.server 8000
npm ci
npm test
npm run check
```

Затем открыть `http://localhost:8000/`. Для офлайн-режима нужен HTTP localhost или HTTPS, открытие через `file://` не поддерживается. Сборка не требуется. npm-зависимости используются только в тестах, клиент работает без внешних библиотек.

Тесты используют Node, fake-indexeddb и linkedom: расчёты, перенос данных, очередь, конфликты, сохранение во время синхронизации, изоляция аккаунтов, очистка HTML, структура экранов и локальные ресурсы. Это не проверка Safari/Chrome и не тест реального входа в пользовательский аккаунт. Перед дальнейшими изменениями проверяйте ввод, выделение и undo в этих браузерах.

## Данные и совместимость

Основное хранилище: `seeker-notebook-3:guest` и отдельная IndexedDB `seeker-notebook-3:<user-id>` для каждого аккаунта. Object stores: `records`, `drafts`, `media`, `queue`, `meta`.

Сущности `party`, `character`, `session`, `section` содержат `id`, `created_at`, `updated_at`, `version`, `device_id`, `deleted_at`. История, события и снаряжение представлены форматированными секциями, что сохраняет простоту журнала. Модификаторы не хранятся.

При первом открытии прежний `seeker-chronicles:v2` переносится из localStorage, а обложки из `seeker-chronicles-media-v2`. Сохраняются сессии, отряд, цель, даты, текст и изображения. Оригинальная копия дополнительно сохраняется в IndexedDB. Старое хранилище не удаляется и больше не обновляется. Миграция повторно не запускается. Не открывайте прежнюю версию приложения для записи одновременно с новой.

Изображения уменьшаются до 1600 px, миниатюры до 320 px, сохраняются как JPEG. Новый файл получает новый идентификатор. Исходное соотношение сторон сохраняется, отображение обложек использует `object-fit: cover`.

## Облако

Используется существующий Supabase-проект, Auth email/password, закрытый bucket `player-notebook-covers` и таблица `player_notebook_state`. Схема не менялась: нормализованные клиентские сущности сохраняются в её JSONB `data.records` с маркером `format: seeker-notebook-3`. Предыдущие данные внутри JSON не удаляются.

Конфигурация в `notebook/cloud.mjs` содержит только существующий **publishable** ключ, предназначенный для браузера. Secret/service-role ключей нет. PostgreSQL RLS ограничивает строки по `auth.uid() = user_id`; Storage ограничивает пути папкой пользователя. Перед подключением другого проекта нужно создать эквивалентную таблицу и политики.

Вход сам по себе не заменяет данные: пользователь выбирает объединение локального журнала с аккаунтом либо открытие только записей аккаунта. Локальные записи гостя и каждого аккаунта изолированы. После выхода записи аккаунта остаются в его IndexedDB и доступны при следующем входе, гостевой журнал сохраняется отдельно.

Каждое изменение и запись очереди атомарно сохраняются локально. Очередь содержит `id`, `entity_type`, `entity_id`, `operation`, `payload`, `created_at`, `retry_count`. Синхронизация запускается после изменения, возвращения сети и раз в 30 секунд. Изображения загружаются до подтверждения данных. Ошибка оставляет очередь и локальные данные на устройстве.

Синхронизация использует трёхстороннее объединение по полям относительно последней подтверждённой копии. Конкурирующие версии текста и удаления сохраняются в `conflicts`; интерфейс позволяет выбрать каждую версию. Запись облачного снимка защищена условием `client_updated_at = <прочитанное значение>` (compare-and-swap); при гонке снимок перечитывается. Подтверждение удаляет только реально отправленные операции. Новые локальные изменения, сделанные во время запроса, сохраняются.

## Файлы

- `index.html`, `notebook/book.css`: оболочка и адаптивный интерфейс.
- `notebook/app.mjs`, `text.mjs`: взаимодействия, чтение/редактирование, очистка HTML, изображения и резервные копии.
- `notebook/model.mjs`, `db.mjs`, `cloud.mjs`: модель, миграция, IndexedDB и синхронизация.
- `service-worker.js`, `manifest.webmanifest`, `assets/`: офлайн-ресурсы, материалы и шрифты.
- `tests/`: проверки поведения и защиты данных.

Прежние файлы интерфейса не подключены новой оболочкой и сохранены в репозитории для истории. Другие приложения, включая `peace-predictor`, не изменены.

## Ограничения проверки

Автоматические тесты не заменяют проверку физического iPhone и реальной синхронизации между двумя пользовательскими устройствами. Локальная база, как и раньше, зависит от сохранности данных сайта в браузере: экспорт позволяет сохранить отдельную копию. Система не выполняет физическую очистку мягко удалённых данных и старых изображений.
